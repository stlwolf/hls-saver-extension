# HLS Stream Saver

Chromeで再生のために取得されたHLSレスポンスを、一時的に蓄積して結合出力する拡張です。保存のための再リクエストは行いません。Manifest V3、デスクトップ版Chrome 120以降を対象とします。

## Chromeにインストールする

必要なのはデスクトップ版Chrome 120以降と、このリポジトリのファイルです。Chrome Web Storeからではなく、手元のフォルダから読み込みます。通常の利用にNode.js・npm・ビルドは不要です。ffmpegも、後からMP4へ変換するときだけ必要です。

1. GitHubのリポジトリ画面で試したいブランチを選び、**Code → Download ZIP**でダウンロードして展開します。すでにclone済みなら、そのフォルダを使えます。選ぶのは`manifest.json`が入っているフォルダで、ZIPファイル自体ではありません。
2. Chromeのアドレスバーに`chrome://extensions`を入力します。
3. 右上の「デベロッパーモード」をONにします。
4. 「パッケージ化されていない拡張機能を読み込む」を押し、手順1のフォルダを選びます。
5. 拡張一覧に「HLS Stream Saver」が表示され、有効になっていることを確認します。
6. Chromeのツールバーの拡張機能メニュー（パズルのアイコン）を開き、「HLS Stream Saver」をピン留めします。ツールバーから操作画面を開けるようになります。

フォルダが認識されない場合は、`manifest.json`がそのフォルダの直下にあるか確認してください。読み込んだフォルダは、利用中に移動・削除しないでください。Chromeへの読み込み方法は[Chrome公式の手順](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)も参照できます。

## 再生して結合保存を試す

トップページのJavaScriptがfetch/XHRでHLSを取得する動画ページを使います。最初は短い範囲で試してください。

1. 対象の動画ページを開き、ツールバーの「HLS Stream Saver」を押します。収録がOFFなら「収録をONにする」を押します。「対象ページをリロードしてから再生してください」と出る場合は、先にそのページをリロードして操作画面を開き直します。
2. 収録をONにした状態で、対象ページをもう一度リロードしてから動画を再生します。再生開始前のプレイリストから取得するためです。このリロードで以前の蓄積は削除されます。
3. 少し再生して操作画面を開き、「動画断片の保存完了」の件数と「蓄積容量」が増えていることを確認します。「プレイリスト保存済み」は動画本体とは別の件数です。初期値はONで、新しいページでは最後に選んだON/OFFを引き継ぎます。
4. 「収録をOFFにする」を押します。「停止処理中」が消え、「保存待ち」が0件になるまで待ちます。動画の一時停止・終了だけでは収録はOFFになりません。
5. 「結合して書き出す」を押します。開いた専用画面でプレイリストを選び、「保存先を選んで書き出す」から保存場所を指定します。元の動画ページは閉じず、リロードもしないでください。
6. 「書き出しが完了しました」と表示されたら、選択した保存先に`.ts`または`.m4s`のファイルが1本できたことを確認します。必要なら[ローカルでの変換](#ローカルでの変換)の手順でMP4に変換します。

書き出し対象は、ボタンを押した時点で拡張が受付済みの断片です。ONのまま書き出すこともでき、その後に届いた断片は次回の対象になります。プレイヤーの先読み分も含むため、実際に画面で視聴した時間と出力の長さが一致するとは限りません。

蓄積とON/OFFはタブごとに独立しています。画質・映像・音声が別プレイリストの場合は、別の出力候補として表示されます。1プレイリストの収録範囲を1ファイルにまとめます。別音声の多重化やMP4への自動変換は行いません。

## ファイルを更新したとき

必要な収録データは、更新前に書き出してください。旧版から更新する場合は、旧版の「Clear」で不要データを消しておきます。

1. 読み込み元のフォルダを、使いたい版のファイルで更新します。clone済みなら使いたいブランチ・コミットへ切り替えます。
2. `chrome://extensions`で「HLS Stream Saver」の再読み込みボタン（円形の矢印）を押します。拡張の再読み込みで蓄積データは失効します。
3. 対象の動画ページもリロードし、上の「再生して結合保存を試す」から確認します。拡張の再読み込みだけでは、すでに開いていたページの処理は更新されません。

## うまく動かないとき

| 状態 | 確認すること |
|---|---|
| アイコンが見つからない | 拡張機能メニューで有効化とピン留めを確認する |
| 動画断片の保存完了が0件のまま | ONを確認してページをリロードし、再生する。iframe・Worker・ブラウザ内蔵プレイヤー経由は対象外 |
| プレイリストがないと言われる | ONにした状態でリロードし、動画を最初から再生する |
| 欠落や保存失敗が表示される | 「蓄積をクリア」で失敗した収録を削除し、ONにしてリロード後に収録し直す |
| 書き出し画面でデータが削除されたと出る | 元のページを閉じたりリロードしたりすると、その収録は復元できない。元のページで収録し直す |
| 使うのをやめたい | 必要なファイルを書き出してから対象ページを閉じ、`chrome://extensions`で無効化または削除する |

## データの寿命

| 操作 | 一時データ |
|---|---|
| OFF | 受付済みの保存を完了し、蓄積を保持 |
| 書き出し完了・書き出し中止 | 蓄積を保持。再度書き出し可能 |
| クリア | 対象ページの蓄積を削除し、対象の書き出しを無効化 |
| リロード・ページ移動・タブを閉じる | 対象ページの蓄積を自動削除 |
| ブラウザ終了・クラッシュ | 残存データを次回の拡張初期化時に削除 |
| Service Workerの休止・再起動 | 同じブラウザ実行中・同じページの蓄積を保持 |
| 拡張の再読み込み・更新 | 前回の実行の蓄積を次回初期化時に削除 |

書き出し中も元のページを開いておいてください。元のページを離れると書き出しを中止します。書き出し済みのファイルは自動削除しません。終了時の削除処理を保証できないため、ブラウザ終了直後にはディスク上に一時データが残る場合があります。

旧版が使っていた`HLSSaverDB`はページとの対応が記録されていないため、新版では読み出し・自動削除を行いません。旧版から更新する際に未出力データがある場合は、旧版で必要な出力と「Clear」を済ませてください。新版の一時保存先は`HLSSaverCaptureDB`です。

## 結合できる範囲

- 同じmedia playlistの連続した、暗号化されていないMPEG-TS。
- TSは188バイトのパケット単位であることを確認し、空の断片や末尾が欠けた断片は出力しません。
- 同じ初期化断片を使うfMP4。再生で初期化断片も取得されている必要があります。
- プレイリストが更新される場合は、取得した更新履歴から断片の順序を復元します。
- `EXT-X-DISCONTINUITY-SEQUENCE`による不連続も検出します。`EXT-X-SKIP`を使う差分プレイリストの結合は未対応として表示します。
- BYTERANGEは保存したContent-Rangeと一致する場合に対応します。CDNのCORS設定でContent-Rangeが見えない場合は、範囲を確認できないため出力しません。
- 収録範囲の前後が未取得なら、その範囲だけを出力して警告します。途中の欠落・不連続・初期化情報変更・暗号化はエラーにします。

プレイリストが取れていない場合、到着順やファイル名からの推測で結合しません。ONにしてからページをリロードして再生してください。iframe、Worker、ブラウザ内蔵プレイヤーなど、トップページのfetch/XHRフックを通らない取得は対象外です。拡張子のないURLも対象外です。

未対応・不正なプレイリストが含まれる場合も、別の対応プレイリストは選択して出力できます。結合できない候補には「結合不可」と表示し、選択したときに理由を表示します。

## 容量と負荷

動画本体はIndexedDBへ192 KiB以下のチャンクで保存します。ポップアップの統計更新では本体を読みません。出力は専用画面から断片を順次読み出してファイルへ書き込み、全動画を配列・Blob・DataURLにまとめません。

ページ読み込み直後、収録設定が届く前のレスポンスは設定が届くまで保存用の読み取りを待ちます。再生用のレスポンスはそのまま返します。最初の設定がONなら保存し、OFFなら保存用コピーを破棄します。設定待ちは最大10秒で、初期化が間に合わずデータを保持できなかった場合はエラーを表示します。

書き出しではプレイリストの更新履歴を1件ずつ読み、断片の順序情報へまとめます。解析済みの本文は保持し続けません。

1レスポンスにつき192 KiB以下のチャンクを1個ずつ送り、保存完了の応答を待って次を送ります。処理中のレスポンスは32件、1レスポンスは32 MiB、プレイリストの読み出しは2 MiBを上限とします。受信が30秒間進まない場合や保存先から10秒間応答がない場合は、収録を止めてエラーを表示します。進捗がある収録の合計時間には30秒の制限を設けません。`Response.clone()`の内部バッファや、読み取り済みの元チャンクは転送中のチャンクとは別であり、ブラウザ全体のメモリに厳密な上限を保証するものではありません。

「エラーで収録停止」と出た収録は自動再開しません。保存待ちの件数が減っても、それは受付済みデータの処理です。欠落がある状態ではONと書き出しを禁止します。「蓄積をクリア」してからONにし、ページをリロードして収録し直してください。保存完了の件数だけでは動画の冒頭から揃ったことを保証しません。収録範囲と連続性は、書き出し時に取得済みプレイリストと照合します。

保存待ちの断片は最終チャンクから30秒経過すると期限切れです。定期回収は1分ごと、統計更新時にも行います。ブラウザのストレージ容量不足はエラーとして扱います。

## ローカルでの変換

```bash
ffmpeg -fflags +genpts -i recording.ts -c copy -movflags +faststart recording.mp4
ffmpeg -i recording.m4s -c copy -movflags +faststart recording.mp4
```

## 開発と検証

実行時の外部ライブラリはありません。Node.js 20以降でテスト用依存をインストールします。

```bash
npm ci
npm test
npx playwright install chromium
npm run test:browser
```

ブラウザ検証には`ffmpeg`と`ffprobe`も必要です。新規の一時プロファイルとローカル配信サーバーを使い、普段のChromeプロファイルには接続しません。既存のChromiumを使う場合は`PW_CHROMIUM_EXECUTABLE_PATH`で実行ファイルを指定できます。

ブラウザテストの保存先選択は自動化用にOPFSのファイルハンドルへ置き換えます。書き込みは実際のFileSystemWritableFileStreamを使い、TS/fMP4をffprobeで検証します。OSの保存ダイアログそのものは自動化していません。

内部構成と採否は[DESIGN.md](DESIGN.md)を参照してください。
